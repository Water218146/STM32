## 1. PWM波形有毛刺/振铃

**现象**：示波器观察PWM输出（PA6），方波边沿有明显振铃和毛刺。

**原因**：GPIO翻转速度过快（50MHz），信号边沿的高频分量在PCB走线上产生反射。

**解决**：降低GPIO输出速度，从 `GPIO_Speed_50MHz` 改为 `GPIO_Speed_2MHz`，PWM频率只有1kHz，2MHz完全够用。

**教训**：
> GPIO速度不是越快越好，要根据实际信号频率选择合适的速度等级。

## 2. Timer3 PWM与中断功能冲突

**现象**：项目中同时存在 `TIM3_PWM_Init()` 和 `Timer3_Init()` 两个函数，都在配置TIM3，导致后初始化的覆盖前面的设置。

**原因**：两个函数独立配置同一个定时器，参数互相覆盖。

**解决**：合并为一个函数 `TIM3_PWM_Init(arr, psc)`，同时配置PWM输出和定时中断：

```c
void TIM3_PWM_Init(uint16_t arr, uint16_t psc)
{
    // 1. GPIO AF配置（PA6 → TIM3_CH1）
    // 2. 时基配置（arr, psc）
    // 3. PWM输出配置（OC1, PWM Mode 1）
    // 4. 中断配置（TIM_IT_Update）
    // 5. NVIC配置
}
```

**教训**：
> 同一个外设的所有功能应集中在一个初始化函数中，避免多处配置互相覆盖。

## 3. ADC采集值超过4095（几万）

**现象**：12位ADC理论最大值4095，但串口打印 `adc_raw` 达到20000+，`voltage` 显示17V+。

**排查过程**：

| 排查方向 | 结果 |
|---------|------|
| ADC_ChannelConfig 调用次数 | ✅ 只有一处，正常 |
| ADC_GetConversionValue 返回类型 | ✅ uint16_t，正常 |
| printf格式符 %d vs %u | ⚠️ 小问题，但不是主因 |
| 左对齐 vs 右对齐 | 🔴 **关键线索** |

**关键发现**：将读取值右移4位后数据正常 → 说明数据实际上是**左对齐**存放的（数据在bit[15:4]）。

**疑问**：明明配置了右对齐，为什么实际是左对齐？→ 见问题5

## 4. ADC配置写入无效（寄存器值不对）

**现象**：通过调试代码直接读取ADC寄存器：

```
[ADC_Debug] CFGR1=0x0000202F
[ADC_Debug] RES bits(bit4-3)=1, ALIGN bit(bit5)=1
```

**期望** vs **实际**：

| 配置项 | 代码中设置 | 寄存器实际值 |
|-------|-----------|------------|
| 分辨率 RES[1:0] | 00（12位） | 01（10位）❌ |
| 对齐方式 ALIGN | 0（右对齐） | 1（左对齐）❌ |
| DMA使能 DMAEN | 0（关闭） | 1（开启）❌ |

**结论**：`ADC_Init()` 函数写入的值被"污染"了。→ 见问题5

## 5. 根本原因：栈上结构体未初始化 ⭐

**这是所有ADC问题的根本原因。**

### 问题代码

```c
ADC_InitTypeDef ADC_InitStructure;    // ⚠️ 栈上分配，成员值是随机垃圾！

ADC_InitStructure.ADC_Resolution = ADC_Resolution_12b;
ADC_InitStructure.ADC_ContinuousConvMode = ENABLE;
ADC_InitStructure.ADC_ExternalTrigConvEdge = ADC_ExternalTrigConvEdge_None;
// ❌ 漏掉了 ADC_ExternalTrigConv，里面是随机垃圾值！
ADC_InitStructure.ADC_DataAlign = ADC_DataAlign_Right;
ADC_InitStructure.ADC_ScanDirection = ADC_ScanDirection_Upward;

ADC_Init(ADC1, &ADC_InitStructure);
```

### 原因分析

```
栈上未初始化的结构体
    ↓
ADC_ExternalTrigConv = 随机垃圾（如 0x2F）
    ↓
ADC_Init() 内部用 OR 操作合并所有字段写入 CFGR1
    ↓
垃圾值的各个bit污染了寄存器：
  • Bit[5] = 1  →  ALIGN = 左对齐
  • Bit[4:3] = 01  →  RES = 10位分辨率
  • Bit[0] = 1  →  DMAEN = 开启DMA
```

### 正确写法

```c
ADC_InitTypeDef ADC_InitStructure;
ADC_StructInit(&ADC_InitStructure);    // ✅ 先填入默认值，所有字段清零

ADC_InitStructure.ADC_Resolution = ADC_Resolution_12b;
ADC_InitStructure.ADC_ContinuousConvMode = ENABLE;
ADC_InitStructure.ADC_ExternalTrigConvEdge = ADC_ExternalTrigConvEdge_None;
ADC_InitStructure.ADC_DataAlign = ADC_DataAlign_Right;
ADC_InitStructure.ADC_ScanDirection = ADC_ScanDirection_Upward;
ADC_Init(ADC1, &ADC_InitStructure);
```

### 核心教训

> **所有STM32标准库的 `XXX_InitTypeDef` 结构体，使用前必须先调用 `XXX_StructInit()` 初始化！**
>
> 栈上的局部变量不会自动清零，未赋值的成员包含内存中的随机垃圾。
> 标准库的 `Init` 函数使用 OR 操作合并各字段，垃圾值会直接写入寄存器。

### 通用防范措施

```c
// 方法1：使用 StructInit（推荐）
GPIO_InitTypeDef GPIO_InitStructure;
GPIO_StructInit(&GPIO_InitStructure);

// 方法2：手动清零
ADC_InitTypeDef ADC_InitStructure = {0};

// 方法3：memset
memset(&ADC_InitStructure, 0, sizeof(ADC_InitStructure));
```

## 📋 经验速查表

| 类别 | 要点 |
|-----|------|
| GPIO速度 | 根据信号频率选择，不要无脑50MHz |
| 外设初始化 | 同一外设的功能集中在一个Init函数 |
| 结构体初始化 | **必须先 StructInit 或 = {0}** |
| ADC对齐方式 | 右对齐：数据在bit[11:0]，左对齐：数据在bit[15:4] |
| 调试手段 | 直接读寄存器值，和期望值对比 |
| printf格式 | uint16_t 用 `%u`，不要用 `%d` |
